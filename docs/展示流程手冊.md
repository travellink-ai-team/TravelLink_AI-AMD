# TravelLink AI 現場展示流程

這份流程供固定場地的電腦展示使用。主軸是讓觀眾從「建立 → 編輯 → 出遊 → 照片 → 回顧」看完一次使用體驗；虛擬 GPS 只替代實際移動，不假裝照片或打卡已寫入正式紀錄。

## 展示前準備

1. 使用正式網站 `https://travel-link-ai.duckdns.org/`，重新整理時用 `Ctrl+F5`。確認 Google 地圖、`/api`、Firebase 與瀏覽器主控台沒有紅色錯誤。
2. 準備一個可登入的展示帳號，以及一趟至少三個景點、有座標和路線的備用行程。用備用行程網址另開分頁，附加 `demo=1`（已有 `?` 時用 `&demo=1`）。不要在正式旅程上按「開始行程」來做彩排。
3. 準備不同拍攝時間、亂序命名的示範照片，至少包括一張缺 EXIF 的照片。若要展示多人相簿，預先讓第二個帳號加入同一趟行程，並用另一個 Chrome Profile 登入；兩個分頁不能代替兩個 Profile。
4. 準備完成的拼貼或回顧短片作為離線備援。現場網路、地圖或 AI 服務故障時，仍能說明最終成果；預錄內容要標示為預先製作。

## 主展示（約 8–12 分鐘）

| 段落 | 現場操作 | 觀眾應看到 |
|---|---|---|
| 建立 | 從「探索與建立行程」選範本，或走一次建立精靈；展示目的地、時間、交通、偏好與預覽，再產生行程。 | 輸入條件如何變成站點與時間表。AI 生成若耗時，切到事先準備的備用行程。 |
| 編輯 | 開啟行程，在桌機點一站使用右側編輯抽屜，調整停留／時間；再看地圖及路段。 | 行程、預覽、地圖與路線同步。手機版可展示底部「行程／現在景點／地圖」切換；路線卡預設收合，點開看各段，`⋯` 內看替代路線。 |
| 出遊 | 在備用行程網址附加 `demo=1`，按「展示模擬」。手機寬度會自動切到地圖；展開工具列，以搖桿或鍵盤方向鍵移動，也可用播放、速度、下一站。 | 虛擬定位沿路線前進；已走路段逐漸變灰，抵達與照片提醒按順序出現。按「結束模擬」回到原本正式狀態。 |
| 照片 | 在「旅記」按「批次上傳並自動整理」，選取預先準備、上傳順序打亂的照片；開「共同行程相簿」。 | 照片依拍攝時間／位置與景點分組，並非依選檔順序。缺資訊或低信心照片進「待整理」，示範手動更正景點與順序。多人照片顯示上傳者。照片上傳屬正式資料操作，請使用展示專用行程。 |
| 回顧 | 在「旅記」開「製作旅程回憶」，展示九宮格或回顧短片的預覽與輸出；最後展示一張成品與 QR Code。 | 觀眾看到可以帶走的成果，而非只看到規劃畫面。模擬工具列的「展示回顧」僅是模擬事件摘要，不等於正式 MP4。 |

## 操作邊界與失敗備案

- `?demo=1` 僅啟用這個分頁的模擬位置、虛擬時間、路線進度及提醒；不寫入正式打卡或行程狀態。照片上傳、編輯、AI 生成仍是正式功能，彩排時使用展示專用行程。
- GPS 吸附模式適合快速展示整條路線；自由移動可說明搖桿，但偏離路線太遠時不應把灰線往前推。當某段 Directions 不可用，系統可能顯示直線示意，現場需如實說明。
- 若 Google Maps、AI 或網路暫時失敗，切換到備用行程、已準備的相簿和預錄短片；不要把備用內容說成當下即時生成。
- 每次正式彩排都檢查：開始和結束模擬前後行程狀態相同、灰線沒有留縫、手機地圖拖動後沒有永久白塊、景點頁返回行程正常、照片手動分類不會被同步覆蓋。

## 尚需實機驗收

這份流程不能代替現場的 iPhone／Android、真實 GPS 與兩人不同帳號測試。正式發表前，至少各跑一次手機路線拖動、實際定位偏離／回到路線、不同品牌照片 EXIF、缺 EXIF 照片、雙帳號同時上傳和同步。
