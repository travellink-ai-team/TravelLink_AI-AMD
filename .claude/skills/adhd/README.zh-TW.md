## 這是什麼

一個**發想用的 skill**。它解決的問題是:AI 回答開放式問題時,傾向給出「資深工程師三十秒內
會講的那三個答案」——正確,但無聊,而且大家都想得到。

它的做法是把「發散」和「收斂」硬性拆開:

1. **發散階段**:同時開 5 個**互相看不到對方**的分身,每個戴不同的「認知框架」
   (監理官、生物學家、速通玩家、10 歲小孩、$0 預算…),各自產出 6 個點子,
   **禁止評價、禁止排序**,而且明文禁用「前三個顯而易見的答案」。
2. **收斂階段**:另一個評審把 30 個點子打分(新穎度／可行性／切題度)、
   依「底層角度」分群、標出陷阱,再挑前 3 名深入展開成具體做法。

關鍵在於**分身之間必須隔離**。如果讓它們循環著看彼此的輸出,就會互相錨定,
整套方法會塌縮成「一個比較廣的想法」,失去意義。

## 什麼時候用

**適合:**
- 架構決策(「共編的資料同步該怎麼設計」)
- 命名(產品名、API 名、資料表欄位)
- 對外介面設計(SDK / API surface)
- 找不到根因的模糊 bug(「偶發性同步失敗,查不到規律」)
- 產品方向(「空檔助手這個概念還能怎麼切」)

**不適合(它自己會擋掉):**
- 語法問題、查文件
- 已知根因的 bug
- 你講了「快速」「標準」「慣例」「就…」這類收斂字眼——代表你要的是直接答案

## 成本(先看這個再決定要不要用)

**每跑一次約 10 個 Agent 呼叫,30–90 秒,約是一般回答的 5–10 倍。**

這在你的用量上是實打實的支出。它內建了 pre-flight 檢查會擋掉不值得的情況,
但**只要你打 `/adhd` 就會直接略過檢查開跑**(視為你主動選擇)。
所以別把它當成一般提問的替代品。

## 怎麼用

### 明確叫用(略過所有檢查,直接跑)

```bash
/adhd 空檔助手的寄物櫃資料沒有來源，還有什麼方式能解決「拖著行李」這個問題
```

也可以用自然語言:「用 adhd 想一下…」「ADHD mode:…」

### 讓它自己判斷

不打 `/adhd`,只是問一個開放式問題時,它會自問三題:
是否開放式?代價是否夠高?你的用詞是否開放?
**三題全過才會啟動**,任一不過就直接正常回答你。

## 輸出長什麼樣

固定五段結構(這個結構本身就是價值的一半,不會被壓成一坨散文):

| 段落 | 內容 |
|---|---|
| **Brief** | 一兩行確認問題,以及有沒有重新框定 |
| **Wide set** | 全部點子依「底層角度」分群,每個附分數 `[N7 V8 F9]`(新穎/可行/切題) |
| **Converge** | 2–4 個短名單,★ 標出「不明顯但可行」的那個;陷阱另外列並說明為何是陷阱 |
| **Focus** | 前 3 名深入:運作方式、**最吃重的風險**、第一步該做什麼、3–5 個衍生點子 |
| **Provocation** | 一個外卡問題,如果上面都沒打中,可以從這裡再挖 |

## 14 種認知框架

每次挑 5 個,程式類問題會偏向 `code`/`design` 標籤,但一定至少帶一個 `wild` 保持廣度。

硬體工程師、監理官、10 歲小孩、想搞垮它的競爭對手、生物學、物流、遊戲設計、
市場機制、反轉思考、$0 預算 1 小時、無限預算 10 年、拿掉最吃重的假設、
速通玩家、蟻群、凌晨三點被 call 起來的值班工程師。

同一個問題重跑會挑到不同框架,所以**再跑一次會得到不同的候選集**。

## 搭配這個專案的建議用法

你手上這幾件事很適合:

```bash
/adhd 空檔助手的「回程時間反推」該怎麼設計才不會在使用者中途改停留時間時算錯
```

```bash
/adhd members schema 從 legacyMemberKey 遷移到 identityKey，怎麼做才能不中斷既有共編行程
```

反過來,**這些別用**(浪費額度,直接問就好):
- 「這個 CSS 為什麼沒生效」
- 「幫我把 X 改成 Y」
- 「commit 上去」

## 已知的坑

原始 skill 自己列了四個失敗模式,值得先知道:

1. **假發散**——30 個點子其實共用同一個假設,那只是裝飾不是廣度。
2. **只發散不收斂**——一堆沒排序的怪點子跟一個安全答案一樣沒用。
3. **拒絕表態**——「這裡有 20 個點子你自己選」是逃避,它應該給出立場。
4. **跳過隔離**——在同一個上下文裡循序寫出「五個分身」不算數,必須真的開平行 Agent。

如果你發現輸出有上述症狀,直接說「這次發散得不夠,重跑」。
