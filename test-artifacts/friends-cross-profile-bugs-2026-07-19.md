## BUG-001：送出好友邀請後發生 JavaScript 例外

- 嚴重程度：高（阻塞好友邀請流程）
- 狀態：已修復（2026-07-21 正式站驗證通過）
- 發生位置：好友邀請搜尋結果的「送出邀請」回呼

### 重現步驟

1. 在 Profile A 開啟「我的好友」。
2. 點擊「加好友」。
3. 輸入 Profile B 的 Email：`tim.lin.930929@gmail.com`。
4. 搜尋並點擊「送出邀請」。

### 預期結果

- 邀請成功寫入。
- 顯示成功提示。
- 按鈕顯示「已送出」或「等待接受」。

### 實際結果

- 按鈕短暫變成 disabled。
- Console 出現紅色錯誤：

```text
TypeError: Cannot set properties of null (setting 'disabled')
```

測試時曾分別看到以下版本的來源位置：

```text
ai-travel-explore-final.js?v=20260719-p2:3522:41
ai-travel-explore-final.js?v=20260714-collab-fix:3510:41
```

### 可能原因

送出邀請完成後，回呼程式嘗試設定已不存在或未渲染的結果按鈕／結果容器的 `disabled` 屬性，未先檢查元素是否存在。

### 實際根因與修復

- `async/await` 返回後，瀏覽器會將 `Event.currentTarget` 清空；錯誤處理再次存取 `ev.currentTarget.disabled`，因此真正的 Firestore 錯誤被二次例外蓋掉。
- 已在 await 前保存按鈕參照，並在更新前檢查元素是否仍連接於 DOM。
- Firestore 錯誤現在會顯示在彈窗內，通知寫入失敗也不會產生未處理 Promise。

### 建議修正

- 在設定 `disabled` 前確認目標元素存在。
- 將邀請寫入、按鈕狀態更新、成功提示拆成可處理失敗的步驟。
- Firestore 寫入失敗時顯示明確錯誤，不要讓 null dereference 中斷流程。

## BUG-002：好友邀請沒有同步到接收端

- 嚴重程度：高（跨帳號功能不可用）
- 狀態：部分驗證通過（邀請建立＋發送端同步正常；接收端待雙 Profile 驗收）

### 重現步驟

1. Profile A 對 Profile B 送出好友邀請。
2. 在 Profile B 重新整理頁面。
3. 進入「我的好友」並查看待處理邀請。

### 預期結果

Profile B 應看到待處理邀請，並可選擇「接受」或「拒絕」。

### 實際結果

- Profile B 的待處理邀請仍為 0。
- 沒有「接受」或「拒絕」按鈕。
- 好友數仍為 0。
- Profile A 重新搜尋相同帳號時，按鈕恢復為可送出狀態，沒有「已送出／等待接受」狀態。

### 影響

好友邀請無法完成跨帳號傳遞，因此後續的接受、拒絕、好友列表同步與共編好友邀請流程全部被阻塞。

### 建議修正

- 確認邀請寫入的 Firestore collection、欄位名稱與接收端查詢條件一致。
- 寫入成功後，在發送端保存 pending 狀態。
- 接收端重新載入時查詢 pending invitations，並顯示接受／拒絕操作。
- 加入一次完整的 A → B → 接受 → A/B 好友列表同步測試。

### 實際根因與修復

`friends.js` 原本會在建立固定 friendship 文件前先執行 `ref.get()` 查重。新文件尚不存在時，Firestore Rules 沒有 `resource.data.emails` 可用來證明讀取者是當事人，因此查重讀取先回傳 `permission-denied`，建立邀請的程式永遠不會執行。

目前已改為：

1. 直接嘗試建立固定 friendship 文件。
2. 只有文件已存在、建立被拒絕時才讀回既有狀態。
3. 依狀態顯示「已送出邀請」、「對方已邀請你」或「已是好友」。

正式站已驗證：

- `tim.lin.930929@gmail.com` 成功送出邀請給 `11211217@gm.nttu.edu.tw`。
- 發送端即時顯示「待確認邀請（1）」及「等待對方確認」。
- 再次送出相同邀請會顯示「已送出過邀請，等待對方確認中」，不會覆寫文件或發生 JavaScript 例外。

## BUG-003：好友邀請視窗沒有關閉按鈕，Esc 無法關閉

- 嚴重程度：中（可用性與無障礙問題）
- 狀態：已修復（2026-07-21 正式站驗證通過）

### 重現步驟

1. 開啟「我的好友」。
2. 點擊任一「➕ 加好友」。
3. 按下 `Esc`。

### 預期結果

視窗應透過右上角關閉按鈕或 `Esc` 關閉。

### 實際結果

- 邀請視窗沒有明確的關閉按鈕。
- 按 `Esc` 不會關閉。
- 只能點擊背景遮罩外部關閉。

### 建議修正

- 加入具備 `aria-label="關閉加好友視窗"` 的關閉按鈕。
- 將好友邀請視窗納入共用 Esc 關閉處理。
- 關閉後將焦點還原到原本觸發「加好友」的按鈕。

### 實際修復與驗證

- 共用操作彈窗新增 44×44 px 的關閉按鈕，`aria-label="關閉加好友視窗"`。
- `Esc` 會優先關閉動態操作彈窗。
- 關閉後焦點會回到原本的「➕ 加好友」按鈕。
- 正式站量測與鍵盤操作均通過。
